# v0.3.16 · 多 GitHub 账号支持 · 设计文档

> 版本：**v0.3.16**　|　日期：2026-09-04　|　状态：📝 设计中
>
> **摘要**：在 v0.3.15 PAT 认证基础上扩展为「账号池」，用户可配置多个 GitHub 账号（每个账号独立 PAT），通过顶栏切换器查看不同账号下的任务。所有任务在 DB 中按 account_id 归属，支持「单账号视图」「全部账号视图」两种模式。

---

## 一、背景与根因

### 1.1 用户诉求

2026-09-04 用户补充需求：「希望可以支持多个 GitHub 账号，可以通过切换查看不同 GitHub 账号上的任务」。

### 1.2 现实场景

- **跨组织开发者**：同时在 `FoodsUp-Inc`（公司）和 `personal`（个人）有任务，期望分别查看
- **多角色**：同一组织里既有自己的 issue，也有作为 reviewer 的项目，需要切换查看
- **团队协作者**：临时帮同事代看，期望加一个同事的账号

### 1.3 当前局限（v0.3.15）

- `meta.pat_token` 单值，只能存一个 PAT
- `meta.login` 单值，sync 用单 login 跑 5 源
- 切账号 = 改 PAT + 清 DB tasks 表重拉
- 不能同时看两个账号的任务

### 1.4 设计原则

| # | 原则 | 说明 |
|---|---|---|
| P1 | 单账号视图优先 | 默认「单账号视图」= 当前激活账号；保证 5 源合并逻辑清晰 |
| P2 | 全部账号可选 | 提供「全部账号视图」聚合所有账号的任务 |
| P3 | 任务归属清晰 | 每条 task 带 `account_id`，切换视图时过滤 |
| P4 | PAT 安全 | 沿用 v0.3.15 的明文存储（v0.3.17 升级 keyring） |
| P5 | 切换成本低 | 顶栏账号切换器一键切换，无需重启 |

## 二、设计目标

### 2.1 一级目标

**支持配置多个 GitHub 账号，每个账号独立 PAT + login + org；提供顶栏账号切换器，支持「单账号视图」与「全部账号视图」两种模式。**

### 2.2 验收原则

| # | 原则 | 说明 |
|---|---|---|
| AC-P1 | 多账号 CRUD | 设置面板可添加/删除/编辑账号 |
| AC-P2 | 独立认证 | 每个账号独立 PAT，单独测试连接 |
| AC-P3 | 顶栏切换 | 顶栏账号下拉切换激活账号 |
| AC-P4 | 单账号视图 | 默认模式：sync 拉取当前激活账号的任务 |
| AC-P5 | 全部账号视图 | 视图模式：sync 拉取所有账号的任务并合并 |
| AC-P6 | 任务归属 | 每条 task 带 `account_id`，切换时过滤 |
| AC-P7 | 存量兼容 | v0.3.15 单账号 DB 自动迁移为「账号池」第一个账号 |
| AC-P8 | MCP 兼容 | MCP 子命令支持指定账号调用 |

## 三、架构设计

### 3.1 数据模型

```
┌──────────────────────────────────────────────────────┐
│ meta 表（保留单值兼容字段）                           │
│ - active_account_id INTEGER（指向 accounts.id）      │
│ - view_mode TEXT DEFAULT 'single' ('single'/'all')  │
└──────────────────────────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────────────────┐
│ accounts 表（新表）                                  │
│ id INTEGER PRIMARY KEY                               │
│ label TEXT NOT NULL  -- "公司 FoodsUp"、"个人"        │
│ login TEXT NOT NULL                                  │
│ org TEXT NOT NULL                                    │
│ pat_token TEXT NOT NULL                              │
│ is_default INTEGER NOT NULL DEFAULT 0               │
│ created_at INTEGER NOT NULL                         │
└──────────────────────────────────────────────────────┘
         │
         │ (1:N)
         ▼
┌──────────────────────────────────────────────────────┐
│ tasks 表（加 account_id 列）                         │
│ + account_id INTEGER NOT NULL DEFAULT 1              │
└──────────────────────────────────────────────────────┘
```

### 3.2 数据流（同步）

```
┌──────────────────────────────────────────────────────┐
│ 用户点「立即同步」                                     │
└──────────────────────────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────────────────┐
│ sync::run() 读 meta.view_mode                          │
└──────────────────────────────────────────────────────┘
         │
         ├── single → 读 active_account_id → 跑该账号 5 源
         │           │
         │           ▼
         │     GitHubClient(login=X, org=Y)
         │           │
         │           ▼
         │     UPSERT tasks SET account_id = X
         │
         └── all → 遍历 accounts 表所有账号
                    │
                    ▼
              每个账号跑 5 源（顺序，有间隔避免突发限流）
                    │
                    ▼
              UPSERT tasks SET account_id = X
```

### 3.3 数据流（切换账号）

```
┌──────────────────────────────────────────────────────┐
│ 用户在顶栏切换账号下拉                                  │
└──────────────────────────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────────────────┐
│ 前端 setActiveAccount(id)                              │
└──────────────────────────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────────────────┐
│ 后端 save_settings({ active_account_id: id })         │
│ UPDATE meta SET value = id WHERE key = 'active_account_id'
└──────────────────────────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────────────────┐
│ 前端 emit('account-changed') → 重新拉取 task 列表       │
│  （account_id = id 或 view_mode = 'all'）              │
└──────────────────────────────────────────────────────┘
```

### 4.2 DB Schema 变更

#### 新表 `accounts`

```sql
CREATE TABLE accounts (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  label       TEXT NOT NULL,
  login       TEXT NOT NULL,
  org         TEXT NOT NULL,
  pat_token   TEXT NOT NULL,
  is_default  INTEGER NOT NULL DEFAULT 0,
  created_at  INTEGER NOT NULL
);
```

#### `tasks` 加 `account_id`

```sql
ALTER TABLE tasks ADD COLUMN account_id INTEGER NOT NULL DEFAULT 1;
```

#### `meta` 加 `active_account_id` 与 `view_mode`

```sql
-- meta 是 key-value 表，新加两条记录（不是 ALTER）
INSERT INTO meta (key, value) VALUES ('active_account_id', '1');
INSERT INTO meta (key, value) VALUES ('view_mode', 'single');
```

### 4.3 v0.3.15 → v0.3.16 自动迁移

`db.rs::init` 检测到 `meta.pat_token` 非空时：

1. 创建 `accounts` 表（如不存在）
2. INSERT 一条记录：`label='默认'`, `login=<meta.login>`, `org=<meta.org>`, `pat_token=<meta.pat_token>`, `is_default=1`
3. 写入 `meta.active_account_id` = 新插入的 id
4. 保留原 `meta.pat_token` / `meta.login` / `meta.org` 字段（兜底，单账号视图仍可用）

### 4.4 sync.rs 改动

```rust
// 旧
let login = db::get_setting(conn, "login");
let gh = github::resolve_gh(&gh_cfg)?;

// 新
let view_mode = db::get_setting(conn, "view_mode"); // "single" | "all"
let accounts = db::list_accounts(conn)?;
let active_id = db::get_setting(conn, "active_account_id").parse().unwrap_or(1);

let target_accounts: Vec<&Account> = match view_mode.as_str() {
    "all" => accounts.iter().collect(),
    _ => accounts.iter().filter(|a| a.id == active_id).collect(),
};

for account in target_accounts {
    let client = GitHubClient::new(account.pat_token.clone(), account.login.clone(), account.org.clone())?;
    // 跑 5 源（每个源带 account_id 写入）
    // 间隔 800ms + 限流感知
}
```

### 4.5 顶栏切换器 UI

`App.tsx` 顶栏新增：

```tsx
<div className="account-switcher">
  <select value={viewMode} onChange={...}>
    <option value="single">单账号</option>
    <option value="all">全部账号</option>
  </select>
  {viewMode === "single" && (
    <select value={activeAccountId} onChange={...}>
      {accounts.map(a => <option key={a.id} value={a.id}>{a.label} (@{a.login})</option>)}
    </select>
  )}
  <button onClick={openSettings}>⚙ 账号设置</button>
</div>
```

### 4.6 设置面板账号管理

`SettingsPanel.tsx` 新增「账号」区块：

| 控件 | 说明 |
|---|---|
| 账号列表 | 每行：label / @login / org / 测试按钮 / 删除按钮 / 设为默认按钮 |
| 「添加账号」按钮 | 弹窗输入 label / login / org / PAT |
| 「测试连接」按钮 | 调 `test_account_pat(id)`，返回 success 或 401/403 |

### 4.7 MCP 改动

`mcp.rs` 的工具接受可选 `account_id` 参数：

```rust
// 旧
list_my_tasks() -> Vec<Task>

// 新
list_my_tasks(account_id: Option<i64>) -> Vec<Task>
// account_id = None → 用 active_account_id
// account_id = Some(0) → 全部账号
// account_id = Some(n) → 该账号
```

## 六、风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 多账号同时同步突发限流 | 🟡 中 | 每个账号之间 800ms 间隔 + 限流感知 |
| account_id 外键孤儿 | 🟢 低 | 删除账号时保留 task.account_id（不级联删除），UI 标记「账号已删除」徽章 |
| 单/全部视图过滤性能 | 🟢 低 | tasks 表加 `idx_account_id` |
| PAT 明文存储 × N | 🟡 中 | 文档提醒；v0.3.17 升级 keyring |
| v0.3.15 迁移失败 | 🟢 低 | 保留 meta.pat_token / login / org 字段兜底 |
| 切换账号 race condition | 🟢 低 | 切换时 disable sync 按钮 + 切换完成后 emit('account-changed') |
| 全部视图任务量大 | 🟡 中 | 全部视图默认收起非 todo 列；点击展开 |

### 回滚方案

如新版本出问题，回滚到 v0.3.15：

- `git revert` 合并 commit
- v0.3.16 自动迁移会创建 accounts 表；回滚到 v0.3.15 时，accounts 表仍存在但代码不读，无害
- 用户手动 DROP TABLE accounts 可完全恢复
