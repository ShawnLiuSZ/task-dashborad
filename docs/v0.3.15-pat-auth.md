# v0.3.15 · 用 GitHub PAT 替代 gh CLI · 设计文档

> 版本：**v0.3.15**　|　日期：2026-09-04　|　状态：📝 设计中
>
> **摘要**：用 GitHub Personal Access Token（PAT）+ `reqwest` 直接调 REST/GraphAPI，彻底替换 `gh` CLI 作为 GitHub 数据获取通道。删除所有 `Command::new("gh")` 与 `resolve_gh` 探测逻辑，消除 gh CLI 引入的 6 类历史包袱。

---

## 一、背景与根因

### 1.1 触发事件

2026-09-04 v0.1.0 三端打包发布后，用户装 CI 产物首次同步失败：5 个 Search 源全部 HTTP 422，DB 只剩 1 条任务。

### 1.2 表层根因

CI 产物首次启动时 `current_login(&gh)` 探测到 `ShawnLiuSZ`（用户此前为开 PR 切换了 gh 活跃账号），但这是 GitHub **listed user**（2009 年前注册类型），Search API 拒绝搜索（HTTP 422 "listed users cannot be searched"）。`meta.login` 写入不可搜索的账号 → 5 源全失败 → `sync::run` 返回 `Err` → DB 完全不写。

### 1.3 深层根因：`gh` CLI 是整套设计的"历史包袱"

| # | 问题 | 表现 | 触发条件 |
|---|---|---|---|
| P1 | 账号切换无感知 | 探测到任意 gh 活跃账号就用 | `gh auth switch` |
| P2 | listed user 限制 | listed user 被 Search API 拒绝 | 某些早期账号类型 |
| P3 | PATH 依赖 | gh 未装或不在 PATH 直接报错 | 干净环境、新机器 |
| P4 | 子进程开销 | 每次 spawn gh + 管道排空 | 大量 API 调用 |
| P5 | 二次限流不可控 | gh 内部退避重试，外部看不到 | 突发请求 |
| P6 | 安装门槛 | 用户必须先 `brew install gh` | 新用户、新机器 |

### 1.4 为什么不能用 gh CLI 的"兜底加固"

| 思路 | 评价 |
|---|---|
| 加 `login` 设置字段 + 探测失败时回退到设置 | ❌ 仍依赖 gh；切换账号后 UI 不会自动感知 |
| `gh auth status` 校验账号是否在 org | ❌ 不能解决 listed user 问题 |
| 保留 gh + 加 PAT 作为并行通道 | ❌ 双路径增加复杂度，且 gh 路径仍是定时炸弹 |
| **完全替换 gh，改用 PAT + reqwest** | ✅ 一劳永逸，符合用户明确诉求 |

## 二、设计目标

### 2.1 一级目标

**用 GitHub Personal Access Token 替代 gh CLI，让 sync 不依赖本地任何外部命令。**

### 2.2 验收原则

| # | 原则 | 说明 |
|---|---|---|
| AC-P1 | 完全脱离 gh CLI | 删除 `resolve_gh` + 所有 `run_gh*`；用户不装 gh 也能跑 |
| AC-P2 | 显式认证 | PAT 由用户自己粘贴到设置面板，可随时更换/清除 |
| AC-P3 | 单客户端全栈共用 | GUI 和 MCP 用同一 `GitHubClient` |
| AC-P4 | 限流可控 | 自己解析 `X-RateLimit-Remaining` + `Retry-After`，主动 sleep |
| AC-P5 | 失败可诊断 | 限流/认证失败时给出明确错误，不静默失败 |
| AC-P6 | 向后兼容（数据层） | DB schema 加字段；旧 DB 自动迁移 |

## 三、架构设计

### 3.1 现状（v0.3.14）

```
┌──────────────┐    spawn    ┌──────┐    JSON    ┌────────────────┐
│ sync::run()  │───────────>│  gh  │──────────>│ GitHub Search  │
│              │<───────────│ CLI  │<──────────│   API / REST   │
└──────────────┘   stdout    └──────┘           └────────────────┘
       │
       │  resolve_gh 探测：
       │    - 用户配置 gh_path
       │    - /opt/homebrew/bin/gh
       │    - /usr/local/bin/gh
       │    - command -v gh
       ▼
  PATH / 安装状态 / 当前登录账号 全部隐式依赖
```

### 3.2 目标（v0.3.15）

```
┌──────────────┐    HTTPS    ┌────────────────┐    HTTPS    ┌────────────────┐
│ sync::run()  │───────────>│ GitHubClient   │───────────>│ GitHub Search  │
│              │            │ (reqwest + PAT)│            │   API / REST   │
└──────────────┘            └────────────────┘            └────────────────┘
       │                            │
       │                            │  - 构造时注入 pat
       │                            │  - 限流主动 sleep
       │                            │  - 错误透传 + 诊断
       ▼
  meta.pat_token（用户设置面板输入）
```

### 3.3 同步数据流

```
App 启动
   │
   ├─ read meta.pat_token
   │     └─ 空 → "请先在设置中配置 PAT" 横幅 + 跳过 sync
   │     └─ 非空 → 构造 GitHubClient(pat)
   │
   ├─ GitHubClient.current_login()
   │     └─ 失败（401/403）→ 横幅「PAT 无效」+ 清 sync 错误
   │
   ├─ 5 源搜索（保留 best-effort）
   │     ├─ assignee:login org:org is:open is:issue
   │     ├─ author:login ...
   │     ├─ mentions:login ...
   │     ├─ commenter:login ...
   │     └─ involves:login ...
   │     └─ 失败源 → eprintln + warning 字段记录
   │
   ├─ PR 拉取（REST /repos/{org}/{repo}/pulls?state=all）
   │     └─ 阶段冷却 4s
   │
   ├─ Project Status（GraphQL）
   │     └─ 阶段冷却 4s
   │
   └─ 评论回源（按预算，预算=12）
```

### 4.2 `GitHubClient` 设计

#### 数据结构

```rust
pub struct GitHubClient {
    pat: String,
    org: String,
    http: reqwest::blocking::Client,
}

impl GitHubClient {
    pub fn new(pat: String, org: String) -> Result<Self, String> {
        if pat.is_empty() {
            return Err("PAT 为空，请在设置中配置".to_string());
        }
        let http = reqwest::blocking::Client::builder()
            .user_agent("TaskBoard/0.3.15")
            .timeout(Duration::from_secs(30))
            .build()
            .map_err(|e| format!("构造 HTTP 客户端失败: {}", e))?;
        Ok(Self { pat, org, http })
    }
}
```

#### 公共方法

| 方法 | 原 gh 等价 | 改写要点 |
|---|---|---|
| `current_login()` | `gh api user --jq .login` | `GET /user` + 检查 401 |
| `search_issues(q)` | `gh search issues q --limit 100 --json ...` | `GET /search/issues?q=...&per_page=100` + 翻页到空 |
| `list_prs(repo)` | `gh api repos/.../pulls?state=all&per_page=100` | `GET /repos/{org}/{repo}/pulls?state=all&per_page=100` |
| `list_comments(repo, n)` | `gh api repos/.../issues/n/comments` | `GET /repos/.../comments?per_page=100` |
| `graphql(query)` | `gh api graphql -F query=@file` | `POST /graphql` body=query |
| `issue_state(repo, n)` | `gh api repos/.../issues/n --jq .state` | `GET /repos/.../issues/n` + `.state` |

#### 限流处理

```rust
/// 检查响应头：主动 sleep 直到 reset，或根据 Retry-After 等
fn handle_rate_limit(resp: &reqwest::blocking::Response) -> Result<(), String> {
    // 1. 主限流（X-RateLimit-Remaining=0）
    if let Some(remaining) = resp.headers().get("x-ratelimit-remaining") {
        if remaining == "0" {
            let reset: i64 = resp.headers()
                .get("x-ratelimit-reset")
                .and_then(|v| v.to_str().ok())
                .and_then(|v| v.parse().ok())
                .unwrap_or(0);
            let wait = reset - now_secs();
            if wait > 0 && wait <= 120 {
                eprintln!("[github] 限流：主动 sleep {}s 等 reset", wait + 2);
                thread::sleep(Duration::from_secs(wait as u64 + 2));
                return Ok(()); // 上层重试
            }
            return Err(format!("GitHub API 限流，等待 {}s（超过 120s 上限）", wait));
        }
    }
    // 2. 二次限流（Retry-After）
    if let Some(retry) = resp.headers().get("retry-after") {
        let s: u64 = retry.to_str().ok()
            .and_then(|v| v.parse().ok()).unwrap_or(60);
        eprintln!("[github] 二次限流：sleep {}s", s.min(120));
        thread::sleep(Duration::from_secs(s.min(120)));
    }
    Ok(())
}
```

#### 调用间间隔

保留 sync.rs 现有的 800ms `thread::sleep`，避免 5 源 + 多仓 PR 形成 Search API 突发限流。

## 六、风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 限流仍存在（Search API 30 req/min） | 🟡 中 | 800ms 间隔 + Retry-After + 主动等 reset |
| PAT 明文存储 | 🟡 中 | 文档提醒用 fine-grained 或短期 token；v0.3.16 升级 `keyring` crate |
| reqwest 依赖增加二进制 | 🟢 低 | ~5MB，可接受 |
| CI 编译时间略增 | 🟢 低 | rustls 无系统依赖，编译稳定 |
| 网络限制（沙箱） | 🟢 低 | 用户环境不受影响；本地 `cargo build` 需 sandbox bypass |
| 回归测试覆盖 | 🟡 中 | 临时副本 cargo test + 手动 UI 验证 |
| listed user 在 PAT 下仍存在？ | 🟢 低 | PAT 认证用 token 而非 username，与 listed user 正交；token 有权限就能调 API |

### 回滚方案

如新版本出问题，回滚到 v0.3.14：

- `git revert` 合并 commit
- 或重新打 tag 指向 v0.3.14 的 commit
- 用户 DB 不受影响（`meta.pat_token` 字段保留无害，v0.3.14 启动时忽略未知字段）

### 10.2 helper 函数签名

```ts
// TaskCard.tsx
function ghStatusCategory(raw: string): "todo" | "doing" | "processed" | "done" | "canceled" {
  if (raw.includes("取消")) return "canceled";
  if (raw.includes("开发中")) return "doing";
  if (raw.includes("测试") || raw.includes("待上线")) return "processed";
  if (raw.includes("完成") || raw.includes("上线")) return "done";
  if (raw.includes("需求") || raw.includes("规划") || raw.includes("待开发")) return "todo";
  return "todo"; // 兜底
}
```
